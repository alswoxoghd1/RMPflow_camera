1. 경영진·개발자용 요약

1.1 현재 무엇이 확인되었는가

판정항목의미
통과접선 기하접선 방향은 단위벡터이며 장애물 법선과 직교하도록 구성된다. 해당 ODE 단위시험도 신선한 빌드에서 통과했다.
구조 통과TG metricMe = me JeTJe이고 me ≥ 0이므로 대칭 양의 준정부호(PSD), rank ≤ 1이다.
조건부목표점 국소 수렴장애물과 TG leaf가 사라지는 clear set에서, metric 비퇴화·잔여항 bound·gain 조건을 실제 수치로 확인할 때만 논문식 국소 지수 안정성 주장을 할 수 있다.
미보장충돌 회피현재 RMP 반발력은 soft policy이다. 경계에서 이미 장애물 쪽으로 움직이는 경우 유한 가속도로는 안전집합 이탈을 막지 못한다는 반례 시험이 코드에 존재한다.
P0센서 고장 대응상위 bridge는 마지막 Range를 freshness 제한 없이 재사용하며, 하위 ECAN은 보관된 원시값으로 계산한 결과에 매 주기 현재 시각을 다시 찍을 수 있다.
P0검증 회귀현재 소스의 CasADi 시험에서 TG가 active로 보고되지만 root metric 기여가 0인 회귀 1건이 재현되며, production 안정성 분석기는 미선언 parameter를 읽다가 실패한다.

1.2 가장 먼저 고쳐야 할 것

  1. stale/invalid 데이터는 “장애물 없음”이 아니라 정지 사유로 처리한다. 센서, 관절 상태, 목표, 실행 flag, TF, 제어 주기의 age와 heartbeat를 한 곳에서 감시한다.
  2. 현재 20개 모델 중 기본 활성 8개인 coverage와 frame mapping을 실물 기준으로 바로잡는다. 단순히 12개를 켜는 것으로 끝나지 않는다. 마지막 8개 frame 이름은 모델의 tof2_1_*/tof2_* 구분과 맞춰 검증해야 한다.
  3. 실측 관절 속도를 확실히 입력한다. params.yaml은 synchronized filter를 켜지만 주 launch 기본값이 뒤에서 false로 덮는다. 감쇠·접근속도 계산에 사용되는 속도가 실제 속도인지 로그로 입증해야 한다.
  4. solver 예외·deadline miss 때 기존 속도를 유지하지 말고 검증된 감속/보호정지로 전환한다. qdd = 0은 “정지”가 아니라 “현재 속도 유지”이다.
  5. TG-RMP 출력을 nominal 명령으로 두고 robust HOCBF-QP 또는 동등한 제동 기반 hard safety filter를 뒤에 추가한다.
  6. 독립 안전 경로를 둔다. watchdog 또는 안전 PLC/안전 기능이 TG-RMP, ROS 2, QP보다 높은 우선순위로 로봇의 보호정지를 명령해야 한다.
운전 제한: 위 P0 항목이 닫히고, 보호거리의 센서 오차·최악 지연·실측 정지거리 budget이 완성되기 전에는 사람이 접근 가능한 상태에서 TG-RMP의 충돌 회피 성능을 시험하면 안 된다. 사람 없는 enclosure와 저속 계측 더미부터 시작한다.

2. 제어를 처음 보는 독자를 위한 설명

비유부터: 목표 RMP는 내비게이션의 “목적지로 가라”, 충돌 RMP는 “장애물에서 멀어져라”, TG-RMP는 “막혔으면 장애물 표면을 따라 돌아가라”는 제안이다. RMPflow는 제안마다 중요도(metric)를 붙여 섞는다. 그러나 안전벨트와 브레이크에 해당하는 것은 별도 hard constraint와 독립 정지 장치다.

2.1 위치·속도·가속도

로봇 관절각을 q, 관절속도를 q̇, 관절가속도를 q̈라고 쓴다. 현재 제어기는 매 주기 목표 관절가속도를 계산하고, 이를 적분해 속도·위치 명령을 만든다. 200 Hz라면 한 주기는 5 ms다.

2.2 RMP와 metric

각 leaf는 “원하는 가속도”와 “그 요청을 얼마나 강하게 반영할지”를 함께 낸다. metric이 크면 해당 leaf의 요청이 root 관절 명령에 더 강하게 반영된다. 여러 leaf를 섞는 능력은 좋지만, 일반적인 metric 가중합은 절대 넘으면 안 되는 거리를 자동으로 강제하지 않는다.

2.3 안정성과 안전성은 다르다

안정성

작은 오차로 시작했을 때 시간이 지나며 목표로 돌아가는가? 자동차로 말하면 핸들을 놓아도 차선 중심 쪽으로 복귀하는 성질이다.

안전성

모든 허용 조건에서 위험 경계를 넘지 않는가? 자동차로 말하면 앞차와의 제동거리 경계를 항상 지키는 성질이다.

목표로 잘 수렴하는 제어기도 그 도중 장애물에 부딪힐 수 있다. 따라서 Lyapunov 목표 수렴 증명만으로 충돌 안전을 주장할 수 없다.

2.4 soft policy와 hard constraint

soft policy는 “가능하면 지켜라”이고, hard constraint는 “물리적으로 실행 가능한 한 반드시 지켜라”다. 현재 TG-RMP와 충돌 RMP는 전자다. 권장 HOCBF-QP safety filter는 후자의 역할을 맡고, constraint 자체가 불가능해지거나 입력이 stale이면 독립 정지 경로로 넘긴다.

4.2 논문의 증명이 보장하지 않는 것

논문 자체도 printed p.9703에서 이 결과가 formal collision-safety 또는 set-invariance 보장이 아니라고 구분한다. 다음은 증명 범위 밖이다.

  • 모든 시간에 최소 안전거리를 유지하는 것
  • 말단이 아닌 로봇 전체 링크의 충돌 회피
  • 움직이는 장애물, closest-obstacle switching, sample-and-hold, 센서 누락을 포함한 안전성
  • 실제 속도·가속도 포화, 추종오차, 통신 지연을 포함한 안전성
  • 장애물이 목표를 점유하거나 정확히 정면에서 접근할 때의 보장

4.3 TG-RMP에 그대로 옮길 수 없는 이유

현재 TG leaf는 접선 방향 ODE 상태, owner hysteresis, 거리·blockage·pocket gate, 포화, 움직이는 장애물 추정이 결합된 hybrid/stateful 정책이다. TG가 목표점에서 active이면 잔여항 d(0,0)=0가 자동으로 성립하지 않는다. 또한 tg_rmp_enable_progress_attenuation=false이므로 과거 finite-well 형태의 안정성 논거는 현재 기본 구성에 적용되지 않는다.

적용 가능한 범위: 목표 주위가 충분히 비어 있어 αTG=0이고 collision leaf도 사라지는 clear set에서만 논문식 잔여항 분석을 시작할 수 있다. 그때도 c₁, c₂, m₀, ε를 실제 코드·포화·이산시간 map에 대해 계산하거나 검증해야 한다. 현재는 그 국소 안정성 수치 판정 결과가 생성되지 않았다.

4.4 논문에서 본받을 실험 설계

논문의 Sec. V는 안전 “증명”보다 성능 “검증 설계”의 좋은 참고다. 장애물 없음 → 정적 → 동적 → 복수 동적 → dual robot으로 난도를 올리고, 최소거리·성공률뿐 아니라 완료시간·경로길이·path-clearing time·sensor-to-command latency를 함께 측정했다. TG-RMP도 같은 틀을 쓰되 아래를 추가해야 한다.

  • 최소거리는 사용 중인 proximity 값이 아니라 외부 ground-truth 거리계/모션캡처로 측정
  • TG OFF/ON, safety filter OFF/ON을 동일 초기조건과 동일 seed로 비교
  • 실패 trial을 제외하지 않은 전체 분포와 최악값 보고
  • dropout, frozen value, 잘못된 timestamp, TF 실패, CPU overload 같은 fault injection
  • 시나리오당 10회보다 충분히 큰 반복과 신뢰구간; 0회 실패도 절대 안전 증명이 아님을 명시

거리 d, clearance rate ḋ, 접선 감쇠계수 be에 대해 desired tangential acceleration은 거리 push, 접근속도 보상, 감쇠를 합친다. 실제 구현은 push를 saturation한다.

ae= sat(ad(d) +ac(d,d˙)) −bey˙
(T-3) TG desired acceleration

권한은 거리·blockage·pocket gate의 곱과 접근속도 gate로 정해진다.

αTG= αdαbαf, me= αTGγmμ d/ℓm+εm
(T-4) activation과 scalar metric

모든 activation과 scalar parameter가 유효 범위에 있으면 me ≥ 0이다. 관절공간으로 pullback한 TG metric과 force는 다음 형태다.

Me= meJeTJe, fe= JeT me (ae−Je˙q˙)
(T-5) canonical natural form pullback

5.2 대수적으로 증명되는 부분

임의의 관절공간 벡터 z에 대해 다음이 성립한다.

zT Mez =me (Jez)2 ≥0
(T-6) TG metric의 PSD 증명

따라서 Me는 대칭 PSD이고, Je가 1×6 행벡터이므로 rank는 최대 1이다. 이는 코드 시험과 별개로 정의에서 바로 나오는 강한 구조적 결과다. 다만 PSD는 “이 leaf가 이상한 음의 가중치를 만들지 않는다”는 뜻이지, 전체 root metric의 양의 정부호성이나 충돌 불변성을 뜻하지 않는다.

5.3 안정성을 아직 증명할 수 없는 부분

  • 비홀로노믹 path-integral leaf: 접선 방향과 누적 progress가 내부 상태이므로 표준 위치 task의 보존 potential로 바로 환원되지 않는다.
  • hybrid switching: 가장 가까운 owner와 hysteresis, activation, pocket gate가 분기한다. 각 모드의 안정성만으로 switching 전체가 안정하다고 할 수 없다.
  • moving obstacle와 추정 ḋ: supervisor의 finite-difference rate는 고정 dt=0.005 가정과 sensor freshness에 의존한다.
  • 현재 energy 선택: tg_rmp_enable_progress_attenuation=false, escape_stability_guard_enabled=false이므로 무한 시간의 에너지 주입 상한이 현재 설정으로 증명되지 않는다. 접선 감쇠는 도움이 되지만 전역 증명은 아니다.
  • 하나의 TG owner: TG는 한 sensor owner를 선택한다. collision leaf는 여러 장애물을 보더라도 복수 장애물 사이에서 접선 탈출 방향의 존재·연속성은 보장되지 않는다.

5.4 충돌 안전집합 반례

clearance에서 보호거리를 뺀 값을 h라 하고 안전집합을 C = {h ≥ 0}라 하자. 경계 h = 0에서 이미 장애물 쪽으로 움직여 ḣ < 0이면, 임의의 유한 가속도에 대해 아주 작은 시간 Δt 뒤에는

h(t+Δt) =h(t) +h˙Δt +12h¨Δt2 +O(Δt3) <0
(T-7) 경계에서 inward velocity가 있으면 distance-only set을 즉시 이탈

1차항 ḣΔt가 2차 가속도항보다 우세하기 때문이다. 저장소의 FullRmpProperties.DistanceOnlyCollisionSetHasBoundaryCounterexample 시험은 바로 이 상황을 구성하고 다음 clearance가 음수가 됨을 확인한다. 즉, 현재 충돌 RMP의 강한 repulsion이나 큰 TG metric만으로 hard safety를 만들 수 없다. 제동거리 또는 relative-degree-2 barrier가 필요하다.

7.2 보호거리부터 측정으로 정한다

현재 0.05 m, 0.15 m 같은 parameter를 안전거리라고 부르면 안 된다. 보호거리에는 물체·로봇 기하, 센서·보정·모델·추종 오차, 반응 중 상대 접근, 로봇 제동거리, 정지 중 장애물 이동이 들어가야 한다.

dunc= esensor +ecal +emodel +etrack
(S-1) 불확실성 budget
dprot= dgeo +dunc +vrel,maxTreact +dstop,rmeas +vo,maxTstop +dres
(S-2) 제안 보호거리 budget
vrel,max: 반응시간 동안의 최대 상대 접근속도, dmeasstop,r: 실제 payload·자세·속도에서 측정한 로봇 제동거리

Treact에는 sensor update, transport, bridge, control compute, command 전송, drive 반응, watchdog 검출이 모두 포함된다. 평균이 아니라 검증한 최악값과 margin을 사용한다. dstop,r은 v²/(2a)만 믿지 말고 실제 RB10·tool·payload에서 독립 계측한다.

7.3 whole-body 안전함수

각 링크/공구의 collision geometry와 장애물 사이 최소거리 dj에 대해 다음 안전함수를 둔다.

hj(q,t)= dj(q,O(t)) −dprot,j, C={(q,q˙)∣hj≥0,∀j}
(S-3) whole-body 안전집합

가속도 명령 시스템에서는 거리에 q̈가 두 번 미분한 뒤 나타나는 경우가 많다. 따라서 relative-degree-2 barrier를 사용한다.

hj¨ +2ζjωjhj˙ +ωj2hj ≥Δj
(S-4) robust exponential HOCBF 형태
Δj는 거리·속도·가속도 추정오차와 이산시간 오차를 덮는 robust margin이다.

이 조건은 초기 상태가 barrier의 허용 상태에 있고, 거리 미분과 불확실성 bound가 맞으며, 매 주기 constraint가 feasible하고, 실제 actuator가 명령을 오차 budget 안에서 추종한다는 전제 아래 사용한다. CBF를 추가했다는 사실만으로 자동 인증되는 것은 아니다.

7.4 TG-RMP를 최소 수정하는 QP safety filter

q¨safe= arg minq¨ 12 ‖q¨−q¨TG‖ W2
(S-5) nominal TG 명령에 가장 가까운 safe 명령

subject to:

  • 모든 활성 링크–장애물 pair의 (S-4) HOCBF constraint
  • 관절가속도 bound와 다음 주기 속도 bound q̇k+1 = q̇k + q̈Δt
  • buffer를 둔 예측 관절위치·workspace/floor constraint
  • 안전 constraint에는 slack을 두지 않음. 성능 constraint에만 제한된 slack 허용

9.3 권장 수치 기준

  • unit test: ‖t‖ − 1 ≤ 10⁻¹⁰, |tᵀo| ≤ 10⁻¹⁰. runtime log는 측정 noise를 고려해 별도 bound(예: 10⁻⁶)를 정한다.
  • metric: 대칭 residual과 최소 eigenvalue가 scale-aware tolerance 안. TG metric rank ≤ 1.
  • root solve: normalized residual ≤ 10⁻⁸, NaN/Inf 0.
  • 안전: 독립 ground truth 기준 h(t) ≥ 0, 모든 링크·tool·floor·joint envelope 위반 0.
  • timing: 200 Hz이면 5 ms deadline. 검증 run에서 miss 0, 실제 제품 정책에서는 single/cluster miss에 대한 stop rule을 명시한다.
  • 고장: fault 주입 후 Tfault 안에 command가 검증된 stop profile로 전환하고, 정지 전까지 보호거리 budget을 넘지 않는다.

9.4 “0번 실패”의 올바른 해석

독립이라고 가정한 N회 시험에서 실패가 0이면, 95% 신뢰수준의 실패확률 상한은 rule of three로 대략 다음과 같다.

pfail95%,upper ≈3N
(V-1) 0-failure rule of three

예를 들어 10/10 성공은 실패확률이 0이라는 뜻이 아니다. Wilson 95% 구간에서 성공률 하한은 약 72.2%다. 실제 robot trial은 서로 독립하지 않을 수 있으므로, 이 통계는 물리적 proof나 인증을 대체하지 않는다.

10.2 각 P0 수정의 구체적인 구현 결과물

  1. Safety supervisor node/library: 각 입력의 steady_clock age, message stamp age, sequence progress, finite/plausibility를 기록하고 NORMAL/DEGRADED/STOP을 publish한다. 최종 command gate는 이 상태를 반드시 소비한다.
  2. Sensor manifest: 20행의 topic, CAN channel, physical serial, frame, parent link, origin, normal, radius, enabled, calibration hash를 단일 소스로 관리한다. 중복·누락·TF 불일치면 startup 실패.
  3. Velocity evidence: encoder position finite difference, controller-published velocity, synchronized filter 출력을 동시에 로그하고 ground truth 또는 high-rate reference와 비교한다. 실기 launch가 하나의 승인된 경로를 강제한다.
  4. Safety filter library: input은 q/q̇, whole-body distance와 derivative bounds, nominal q̈. output은 safe q̈, active constraints, residual, feasibility, fallback reason이다.
  5. Stop profile: q̈=0이 아닌 속도→0 bounded deceleration. 정지 profile의 jerk/accel/robot internal behavior를 실제 하드웨어에서 측정한다.
  6. Fault-injection suite: stale/frozen/NaN/TF loss/node death/solver throw/deadline miss/QP infeasible를 deterministic하게 재현하고 stop time과 마지막 command를 assertion한다.
  7. Release manifest: git commit, compiler, dependency, URDF, sensor calibration, parameter file, payload/tool ID, test artifact hash를 한 묶음으로 보관한다.

10.3 완료의 정확한 정의

TG-RMP 안전성 검증이 “완료”되었다고 말하려면, 적어도 (1) 승인된 ODD가 고정되고, (2) whole-body h와 실측 보호거리 budget이 정의되며, (3) 모든 P0가 닫히고, (4) hard safety filter와 독립 정지 경로가 fault 포함 전 시험에서 동작하고, (5) SiL→HIL→저속 더미→제한 실기의 traceability가 남고, (6) 실제 적용에 필요한 위험성 평가와 PLr/SIL(Safety Integrity Level) 검토가 끝나야 한다.

11. 최종 결론

TG-RMP의 핵심 아이디어—장애물 법선과 직교하는 접선 task를 만들고 rank-one PSD metric으로 root에 합성하는 구조—는 수학적으로 일관되며, 국소 minima에서 빠져나가기 위한 nominal policy로 연구 가치가 있다.

그러나 현재 구성의 safety claim은 다음 수준으로 제한해야 한다.

허용되는 최종 주장
“구조적 건전성 일부 확인, 충돌 안전성은 미검증”
접선·metric의 일부 구조 시험은 통과했다. 목표 수렴성은 clear set의 추가 조건을 확인한 뒤에만 국소적으로 주장할 수 있다. 충돌 safe-set forward invariance, stale/fault 대응, whole-body coverage, 실제 지연·제동거리는 현재 증명·검증되지 않았다.

따라서 TG-RMP를 성능 layer로 유지하면서, robust HOCBF-QP/제동 envelope, freshness/coverage supervisor, solver/deadline fail-safe stop, 독립 보호정지를 추가하는 것이 올바른 다음 단계다. 그 뒤 6단계 verification/validation을 순서대로 통과시켜야 한다.

x_ddot = -kp e - kd v + d(e,v)
||d(e,v)|| <= c1 ||e|| + c2 ||v||,  d(0,0) = 0
V = 1/2 ||v||^2 + kp/2 ||e||^2 + epsilon e^T v
Delta_v = (kd - epsilon) - c2
Delta_e = kp - c1
Gamma = c1 + epsilon*c2 + epsilon*kd
조건: Delta_v > 0,  epsilon*Delta_e > Gamma^2/(2*Delta_v)

[TG-RMP 구조]
||t|| = 1,  t^T o = 0
J_e = t^T J_p,  y_dot = J_e q_dot
alpha_TG = alpha_distance * alpha_block * alpha_free

a_e = sat(a_distance(d) + a_closing(d,d_dot)) - b_e*y_dot
M_e = m_e J_e^T J_e
f_e = J_e^T m_e (a_e - Jdot_e q_dot)
z^T M_e z = m_e (J_e z)^2 >= 0
